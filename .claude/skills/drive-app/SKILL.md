# Drive the app headless

A passing Vitest suite does not prove a view renders. This is how to check it
in the real app, against the local data the dev server already serves.

Visual checks stay the user's call (AGENTS.md) — reach for this when they ask
for screenshot verification, and say what the screenshots show, not what the
checks print.

## Setup (once per session)

Work in the session scratchpad (`$W` below), never the repo.

```bash
W=<scratchpad>
cp .claude/skills/drive-app/drive.mjs "$W"/
cd "$W" && npm init -y >/dev/null && npm i playwright-core
```

`drive.mjs` launches the newest cached Playwright Chromium
(`~/.cache/ms-playwright/chromium-*/chrome-linux64/chrome`). If there is none,
run `npx playwright install chromium` once, or point `TM_CHROME` at a binary.
It launches with `--no-sandbox --use-angle=swiftshader
--enable-unsafe-swiftshader --disable-features=LocalNetworkAccessChecks`: MapLibre needs WebGL, and headless gets it from
SwiftShader; the last flag lets the `sandbox` scenario's loopback third-party page frame the app.

Run it from `$W` so `playwright-core` resolves there. Env: `TM_WORK`
(screenshots and downloads, default `./shots`), `TM_URL` (default
`http://localhost:5199/`, or `http://localhost:4173/` with `--preview`),
`TM_CHROME`.

## Server

```bash
npx vite --port 5199 --strictPort > "$W/vite.log" 2>&1 &   # from the repo root; run_in_background
timeout 40 bash -c 'until curl -sf http://localhost:5199 >/dev/null; do sleep 1; done'
# ...when done:
lsof -ti:5199 -sTCP:LISTEN | xargs -r kill
```

The dev server serves `data/` locally (`DATA_ORIGIN` is empty in dev), so
layers draw from this machine's build, not the published one.

The `csp` scenario needs a production build instead, since the Content
Security Policy is injected at build time only:

```bash
npm run build && npm run preview -- --port 4173 --strictPort > "$W/preview.log" 2>&1 &   # from the repo root
timeout 30 bash -c 'until curl -sf http://localhost:4173 >/dev/null; do sleep 1; done'
cd "$W" && node drive.mjs --preview csp
lsof -ti:4173 -sTCP:LISTEN | xargs -r kill
```

A build reads the **published** data (`DATA_ORIGIN` is the data host), and
has no dev-server modules: `mod`, `st` and `hashFor` do not work there and
`settle` waits a fixed 3 s instead, so `csp` and `chat` drive the app by links and the DOM only. `all`
leaves `csp` out; `chat`, `chart`, `vega`, `canvas`, `sandbox` and `templates` run on both (`node drive.mjs --preview csp chat chart vega canvas sandbox templates`).

The build takes the place-search (Esri) token from `.env.local` in the repo
root. A fresh worktree has none, and then `csp`'s "place search reaches the
geocoder" and `chat`'s two geocoder checks FAIL; copy `.env.local` in from the
main checkout before `npm run build` (never print it).

## What `drive.mjs` already knows (rediscovered the hard way)

- **The first-visit disclaimer** blocks every click. The init script sets
  `localStorage.tm_disclaimer_accepted = "1"` before the page loads.
- **The route and chat usage notices** are pre-accepted the same way: every browser context `launch()` hands out (and every `browser.newContext`) is seeded with `tm-notice-route` and `tm-notice-chat` = `1`; the dialogs themselves are unit-tested.
- **Save view…** falls back to a download only when `showSaveFilePicker` is
  absent; the init script deletes it, and `page.waitForEvent('download')`
  catches the file.
- **Reset calls `window.confirm`.** Headless dismisses dialogs by default, so
  Reset silently does nothing. `open()` accepts confirms and dismisses alerts.
- **Ready** is `#logo` losing its `spin` class. **Settled** is MapLibre's
  `idle` after a short pause: polling `areTilesLoaded()` returns true before a
  just-shown layer or the basemap labels have even requested, and the
  screenshot then shows a half-drawn map while every check passes.
- **App modules import in-page.** Vite serves `await import('/assets/state.ts')`
  as the same instance the app runs, so `mod()` and `st()` drive and read live
  state. Build links with `hashFor()`, which runs the app's own codec
  (`formatUrlState` over `defaultView()`); never hand-encode a `vx`.
- **Notices:** the hidden 3D rotate hint is also `[role=status]`.
  `visibleNotices()` counts only the ones on screen. The dropped-settings
  notice stays up 8 s, so read it straight after `open()`.
- **A canvas or template frame outside the viewport gets no animation
  frames**, so a MapLibre/deck template never reaches `idle` there. Scroll the
  card into view before reading or screenshotting it.
- **A frame's own download**: a model canvas's only adds the page's "Save
  <name>" button to the card (the file arrives on that click); a template's
  (Download ▸ CSV/PNG) saves at once when Playwright clicks inside the frame,
  since a real click there gives the page transient activation and focuses
  the frame — one file per click (the save moves focus out of the frame). A
  download sent from `frame.evaluate` has no gesture and gets the Save button.
- **Read a frame's canvas by sampled pixels, not a hash.** A Vega view repaints
  after a hover with a few pixels changed, so "restored" is a small diff.
- **The red dot on Tools** is the Diagnostics badge; a link with dropped
  settings lights it. Not an error.

### Line tools on a preview build

A build reads `data/analysis/` from the data host (`DATA_ORIGIN`, raw.githubusercontent.com
`data-static`). `datahost.py` (beside this file) stands in for it: HTTPS, GET only
(a preflight gets 403, as raw answers it), `access-control-allow-origin: *` on every reply
(404 too), no `access-control-expose-headers`, single-range 206 with `content-range`,
`.json` as gzip'd `text/plain` when not ranged, binaries as `application/octet-stream`.
With `TM_DATA_HOST` set, `lineRig` rewrites every `data-static` request to it in the
network layer, so the page keeps its URLs and its CSP and the browser's CORS check
meets the stand-in's headers. Both line scenarios also need the dev server (the twin).

```bash
cp .claude/skills/drive-app/datahost.py "$W"/
openssl req -x509 -newkey rsa:2048 -nodes -keyout "$W/key.pem" -out "$W/cert.pem" -days 2 -subj /CN=localhost
python3 -I "$W/datahost.py" "$PWD" 8443 "$W/cert.pem" "$W/key.pem" "$W/host.log" &                       # serves data/layers + data/analysis
HIDE=data/analysis/ python3 -I "$W/datahost.py" "$PWD" 8444 "$W/cert.pem" "$W/key.pem" "$W/host-hide.log" &
# dev server on 5199 and npm run build + preview on 4173, as above
cd "$W" && TM_DATA_HOST=https://localhost:8443/ node drive.mjs --preview lines
TM_DATA_HOST=https://localhost:8444/ node drive.mjs --preview lines-absent
```

Each check prints `PASS`/`FAIL`; the run exits non-zero on any failure, and
`no console errors` closes every scenario. A new scenario is one more entry in
`SCENARIOS`, built from the exported helpers (`launch`, `open`, `settle`,
`mod`, `st`, `hashFor`, `shot`, `visibleNotices`, `check`).

**Canvas-frame console lines (`vega`, `canvas`, `templates` only).** Playwright hands the
page the canvas frame's `console` and `pageerror` events with no frame id.
`chatRig` sorts them by origin: a console line whose URL is `""` (written
code), `…/canvas.html` (the runner) or a CDN/tile host, and a `pageerror`
whose stack is `<anonymous>`, canvas.html or a CDN, go to a "frame console"
log line; everything else stays in `no console errors (the page's own)`. The
refusal steps fill that log on purpose (CSP, popup, form, top navigation).
Expect repeats there: when a new canvas frame attaches, CDP replays the
frame process's earlier console lines, stamped with one identical time —
the probe page did not run again.

## Look at every screenshot

Checks read state; a screenshot is the only proof the map drew it. Open each
PNG before claiming anything. Signs a check missed:

- no transmission lines, or no place names where labels should be on — the
  map had not settled;
- a notice that did or did not appear, or sits over the search box or panel;
- an override painting a companion layer it should not (casings stay white).

Expected, not a regression: with railroads at size ×3, darker dots show where
short rail segments overlap — the layer is slightly translucent, and that
comes from the data.
